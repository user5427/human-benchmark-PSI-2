\sectionnonum{Introduction}
This document presents the request to add real-time chat capabilities to the reaction time training web application. The goal is to improve user interaction  by allowing communication globally and within specific game rooms.

\section{Description}
Create a chat system enabling users to send and receive text-based messages. This system will operate in two scopes:
\begin{itemize}
\item Global scope. Accessible to all logged-in users outside of active game rooms.
\item Room scope. Accessible only to users currently participating within the same active game room.
\end{itemize}
\section{Requirements}

\begin{itemize}

    % UI Structure
    \item The UI must include a togglable chat panel displayed on the right side of the application when the user is logged in.
    \item The chat panel must display a title at the top to indicate its scope:
    \begin{itemize}
        \item \texttt{Global} - all users are able to send, view messages.
        \item \texttt{Room <room-name>} - restricted to users who are currently inside the same active game room.
        \item \texttt{Group <group-name>} - restricted to specific set of users who have been granted access to that group.
        \item \texttt{Private <receiver-username>} - direct one-to-one communication between two users.
    \end{itemize}
    \item The panel must include the following UI elements:
    \begin{itemize}
        \item A scrollable area for message display.
        \item A text input field for message creation, limited to 255 characters.
        \item A \texttt{Send} button for message submission.
    \end{itemize}

    % Message Display
    \item Each displayed message must show the following details:
    \begin{itemize}
        \item Sender's username.
        \item Message timestamp (formatted as \texttt{HH:MM} or similar).
        \item The actual text content.
    \end{itemize}
    \item Messages must be ordered chronologically, with the most recent messages appearing at the bottom.

    % Message Handling
    \item Typing a message and either clicking the \texttt{Send} button or pressing the \texttt{Enter} key must send the message to the server.
    \item After sending a message:
    \begin{itemize}
        \item The input field must be cleared.
        \item The message must immediately appear in the sender's chat panel.
        \item Other users in the same chat scope (global or room) must receive the message in real time.
    \end{itemize}
    \item When the user opens the chat panel for the first time, the system must fetch and display a list of past messages relevant to that chat scope.
    \item If an error occurs during sending:
    \begin{itemize}
        \item A popup notification must appear with the message \texttt{"Failed to send message"}.
        \item The notification must disappear after 3 seconds or when manually closed by the user.
    \end{itemize}
    \item For each received message, the system must determine the correct destination:
    \begin{itemize}
        \item If the message is a direct message to another user, the scope is \texttt{Private <receiver-username>}.
        \item If the message is sent to a specific group, the scope is \texttt{Group <group-name>}.
        \item If the message is sent to a game room, the scope is \texttt{Room <room-name>}.
        \item If the message is broadcasted publicly outside of any room or group, the scope is \texttt{Global}.
    \end{itemize}
\end{itemize}

\section{Impact Analysis}

\section{Implementation options}

\subsection{Develop from scratch}
This involves building the entire chat system end-to-end, including extending database, services and using web sockets for real time communication, as well as developing custom  React components for the chat interface and later maintaining it.
\subsubsection{Pros}
\begin{description}
    \item[Flexibility] Features are not limited to 3rd party capabilities. We can fully develop features, UI/UX, manage data, and integrate new features within existing codebase.
    \item[No 3rd party costs] Avoids recurring subscription fees, which may rise in the future. Costs shift towards infrastructure and maintenance, which can be be lower than 3rd party service costs.
    \item[Data ownership] User data is not stored in extenal database, so we do not rely on 3rd party policies or security measurements for stored user data.
\end{description}
\subsubsection{Cons}
\begin{description}
    \item[High initial investment]  Requires huge time and resource allocation for chat feature development.
    \item[Increased infrastructure costs] Real time chat functionality will increase  Infrastructure(power, data storage, bandwith) fees.
    \item[Risk of bugs] Specialized third-party service is often thoroughly tested and reliable, whereas building a solution from scratch increases the risk of introducing bugs.
\end{description}

\subsection{Use External communication application such as Discord}
 Instead of building chat features directly into the web app, users are encouraged to communicate via  external platform like a dedicated Discord server. 
\subsubsection{Pros}
\begin{description}
    \item[Minimal Development Effort] Requires no coding effort within the core web application itself, aside from potentially adding links or notes related to Discord.
    \item[Many existing features] Discord has rich text, voice channels, emote or file support, roles, bots, mobile apps, and many more.
    \item[No Infrastructure costs] All costs and complexities related to hosting, scaling, and maintaining the chat service are handled by the external platform.
    \item[User Familiarity] Many users may already be familiar with Discord.
\end{description}
\subsubsection{Cons}
\begin{description}
    \item[Poor Integration] Requires users to switch apps to chat, Can be disruptive to the user flow.
    \item[Manual setup for users] Room specific chat logic has to be handled by users.
    \item[Loss of Control] No control over the chat UI or platform availability.
\end{description}


\subsection{Use Third-Party Chat service - Stream}
Use a specialized commercial service that provides chat functionality  via an API and client-side SDKs, such as Stream. Application's frontend integrates the SDK to display chat UI elements, and backend interacts with the service's API to manage users and channels. The third party handles infrastructure.
\subsubsection{Pros}
\begin{description}
    \item[Faster development] Significantly reduces development time compared to building from scratch, as the core functionality is already built.
    \item[Managed infrastructure] Avoid managing WebSockets, scaling connections, ensuring reliability, and handling infrastructure maintenance.
    \item[Additional features included] Often comes with built-in features like presence indicators, typing notifications, message history, read receipts, and moderation tools.
    \item[Decent integration] Allows chat UI to be embedded directly within your web application.
\end{description}
\subsubsection{Cons}
\begin{description}
    \item[Provider costs] Monthly subscription fees based on usage metrics (Monthly Active Users, concurrent connections...) which can become significant if app is popular.
    \item[Difficulty to migrate] Integrating with a specific service makes it potentially difficult and costly to switch providers later.
    \item[Limited customization] Flexibility is bound by the features and customization options offered by the specific vendor; future requirements may be hard to implement.
    \item[External dependency] Chat functionality tied to the third-party service.
\end{description}

\subsubsection{Summary}
Developing from scratch offers the highest flexibility, but requires a high initial investment(assuming team of 3 seniors, all costs included 20.000-30.000€/month) and some ongoing maintenance costs. Using Discord is the cheapest and fastest option but sacrifices integration and control.  Third-party service Stream offers faster development with moderate recurring costs (starting around 400€ per month for up to 10,000 Monthly Active Users, 500 concurrent connections), which, however, could increase significantly as the app becomes more popular, and flexibility is limited by the external service capabilities.

\subsection{Step 1: Identify Duplicates and Similar Terms}
Let’s identify and examine candidate duplicates or terms that may not belong in the domain model:

\begin{itemize}
    \item \textbf{Chat Panel vs. Chat Scope vs. Destination Scope}
    \begin{itemize}
        \item Chat Panel is a UI element.
        \item Chat Scope and Destination Scope are very similar. Let's standardize on Chat Scope and drop "Destination Scope".
    \end{itemize}

    \item \textbf{Input Field vs. Text Input}
    \begin{itemize}
        \item These are describing the same UI element. Let’s keep Text Input.
    \end{itemize}

    \item \textbf{Message vs. Message Content vs. Message Display vs. Message List vs. Past Message}
    \begin{itemize}
        \item These are mostly part-of relationships with "Message".
        \item Let’s keep Message, and treat the rest as attributes or subcomponents of it.
    \end{itemize}

    \item \textbf{Notification vs. Popup Notification}
    \begin{itemize}
        \item “Popup” describes the form, not the concept. Let’s keep Notification.
    \end{itemize}

    \item \textbf{Sender Username vs. Sender vs. User}
    \begin{itemize}
        \item Redundant. We’ll keep only User.
        \item Sender is a role of the User in this context, so we can treat it as an attribute.
        \item Sender Username is a specific attribute of the User.
    \end{itemize}

    \item \textbf{User vs. Customer Account}
    \begin{itemize}
        \item These terms are essentially describing the same concept. Let’s standardize on User and drop Customer Account.
    \end{itemize}
\end{itemize}

\subsection{Step 2: Remove Out-of-Scope or Non-Domain Concepts}

These items are either:

\begin{itemize}
    \item Purely UI,
    \item Too low-level (like primitives), or
    \item Better handled in use cases or elsewhere.
    \item Room ID → implementation detail (likely an attribute).
    \item Message Order → implementation detail (likely an attribute).
    \item TextInput → UI element.
    \item Timestamp → implementation detail (likely an attribute).
\end{itemize}

Let’s remove the following:

\begin{itemize}
    \item \textbf{Character Limit} → implementation detail.
    \item \textbf{Title} → search parameters, not domain entities.
    \item \textbf{Input Sanitization} → non-functional concern (security).
    \item \textbf{UI Element} → overly generic placeholder.
\end{itemize}

\subsection{Step 3: Keep and Rename Where Needed}

Some items are useful but need better naming:

\begin{itemize}
    \item \textbf{System and Server} → Usually architectural layers, not domain entities. Remove.
    \item \textbf{REST Endpoint} → Implementation detail. Remove.
\end{itemize}

\section{Use cases}
Using the updated domain model and the UI mockups, we will try our best to create the use cases for the chat system.
It is likely that we will need to update our domain model once again after creating the use cases.

\subsection{Rough Draft of Use Cases}
Below is a rough draft of the use cases (these are not final, in fact, they do not even include the 'rainy-day' scenarios):
\begin{itemize}
    \item \textbf{Core Chat Functionality}
    \begin{itemize}
        \item \textbf{Send Message}
        \begin{itemize}
            \item User composes and sends a message to a chat (global, room, group, or private) using \textbf{chat window}.
            \item Includes text, emojis using \textbf{emoji window}, and file attachments using \textbf{file upload window}.
        \end{itemize}
        \item \textbf{Switch between Chats}
        \begin{itemize}
            \item User switches between different chat windows using \textbf{chat button}.
            \item System limits number of concurrent chats.
        \end{itemize}
    \end{itemize}

    \item \textbf{Message Management}
    \begin{itemize}
        \item \textbf{Edit Message}
        \begin{itemize}
            \item User modifies a previously sent message using \textbf{chat window}.
            \item System preserves edit history.
        \end{itemize}
        \item \textbf{Delete Message}
        \begin{itemize}
            \item User removes a sent message (with confirmation) using \textbf{chat window}.
        \end{itemize}
        \item \textbf{Pin Message}
        \begin{itemize}
            \item User marks important messages in group/private chats using \textbf{chat window}.
            \item Pinned messages get special visibility.
        \end{itemize}
        \item \textbf{View Pinned Messages}
        \begin{itemize}
            \item User accesses pinned messages in a chat using \textbf{pinned messages window}.
        \end{itemize}
        \item \textbf{Unpin Message}
        \begin{itemize}
            \item User removes the pinned status from a message using \textbf{pinned messages window}.
        \end{itemize}
        \item \textbf{Search Messages}
        \begin{itemize}
            \item User searches message history across different chats using \textbf{search messages window}.
        \end{itemize}
        \item \textbf{View Message History}
        \begin{itemize}
            \item User views past messages in a chat using the same \textbf{search messages window} but without inputting any search parameters.
            \item Messages displayed with sender, timestamp, and content.
        \end{itemize}
    \end{itemize}

    \item \textbf{Chat Management}
    \begin{itemize}
        \item \textbf{Switch Chat Scopes}
        \begin{itemize}
            \item User switches between global and room chat scopes using \textbf{chat button} or when they are in the \textbf{game room}.
        \end{itemize}
        \item \textbf{Create Group Chat}
        \begin{itemize}
            \item User initiates a new group conversation using \textbf{chat creating window}.
            \item Specifies group name and adds participants.
            \item System limits number of concurrent chats.
        \end{itemize}
        \item \textbf{Join Group Chat}
        \begin{itemize}
            \item User requests to join an existing group using \textbf{chat creating window}.
            \item Group owner approves/rejects request.
        \end{itemize}
        \item \textbf{Manage Group Members}
        \begin{itemize}
            \item Group owner adds/removes participants using \textbf{group chat editing window}.
        \end{itemize}
        \item \textbf{Start Private Chat}
        \begin{itemize}
            \item User initiates 1:1 conversation with another user using \textbf{chat creating window}.
        \end{itemize}
        \item \textbf{Delete Chat}
        \begin{itemize}
            \item User removes a private or group chat (with confirmation) using either \textbf{private chat editing window} or \textbf{group chat editing window}.
        \end{itemize}
        \item \textbf{Change Chat Type}
        \begin{itemize}
            \item User switches between global, room, group, and private chat types using \textbf{chat button}.
            \item System limits number of concurrent chats.
        \end{itemize}
    \end{itemize}

    \item \textbf{Notification System}
    \begin{itemize}
        \item \textbf{Receive Notification}
        \begin{itemize}
            \item System alerts user about new messages/events using \textbf{notification window}.
            \item System alers user about invitations to join group chats in the notification window using \textbf{notification window}.
            \item System alers user about removal from group chats using \textbf{notification window}.
            \item System alers user about deletion of group chats or private chats using \textbf{notification window}.
            \item Includes visual and auditory indicators.
        \end{itemize}
        \item \textbf{View Notifications}
        \begin{itemize}
            \item User checks notifications using \textbf{notification window}.
            \item Can jump to relevant message/context using \textbf{notification window}.
        \end{itemize}
    \end{itemize}

    \item \textbf{UI Interactions}
    \begin{itemize}
        \item \textbf{Toggle Chat Window}
        \begin{itemize}
            \item User opens/closes chat windows using \textbf{chat button}.
        \end{itemize}
        \item \textbf{Create Multiple Chats}
        \begin{itemize}
            \item User can have multiple chat windows open.
            \item System limits number of concurrent chats.
            \item User can have only one \textbf{global scope} chat window open.
            \item User can have multiple \textbf{private scope} chat windows open.
        \end{itemize}
        \item \textbf{Upload File}
        \begin{itemize}
            \item User attaches and sends files using \textbf{file upload window}.
            \item System validates file type and size.
        \end{itemize}
        \item \textbf{Select Emoji}
        \begin{itemize}
            \item User adds emojis to messages.
            \item Can browse/search emoji library using \textbf{emoji window}.
        \end{itemize}
    \end{itemize}

    \item \textbf{Administrative}
    \begin{itemize}
        \item \textbf{Moderate Global Chat}
        \begin{itemize}
            \item System enforces character limits for \textbf{chat window}.
            \item Implements spam control measures for the \textbf{global chat}.
        \end{itemize}
    \end{itemize}
\end{itemize}

\subsection{Detailed Use Case Description}
Finally, after all the work we did, we can create a detailed use case description.
Before that, we feel that its very important to mention the difference between chat button and chat window: a chat button is a closed down chat window, that hase some functionality of its own, but it is not a chat window. A chat window is a chat button that is open and has functionality of its own.
\subsubsection{Package: Core Chat Functionality}

\begin{itemize}
    \item 
    Use Case: \textbf{Send Message}

    \textbf{BASIC COURSE:}

    The system displays the chat window. The user types a message in the text input field and clicks the send button. The system sends the message to the server and displays it in the chat window.

    \textbf{ALTERNATIVE COURSES:}

    \textbf{utf8 zero-width characters:}
    User inputs utf8 zero-width space characters in the message. The system removes these characters and sends the message to the server. The system displays the message in the chat window.

    \textbf{empty message:}
    User does not input any message in the text input field. The system does not send the message to the server and displays an error message.

    \textbf{too long message:}
    User inputs a very long message in the text input field (eg. 1000 characters). The system does not send the message to the server and displays an error message.

    \textbf{html editing:}
    User tries to send a message to a group chat or private chat they do not have access to using html editing. The system does not send the message to the server and displays an error message.

    \textbf{cross-site scripting:}
    User inputs a cross-site scripting attack in the message. The system sanitizes the message and sends it to the server. The system displays the message in the chat window.

    \item 
    Use Case: \textbf{Switch between Chats}

    \textbf{BASIC COURSE:}

    The system displays multiple chat buttons. User can click on the chat buttons to open the chat windows. The system opens the chat window and displays the messages in the chat window. User can click on the close button to close the chat window. The system closes the chat window and displays the chat button again.

    \textbf{ALTERNATIVE COURSES:}

    \textbf{there are no chat buttons:}
    The system displays game room and no chat buttons (user has closed down all of them). There are no chat buttons to open the chat windows as a result user cannot open the chat windows. The system does not display any error message.

\end{itemize}

\subsubsection{Package: Message Management}
\begin{itemize}
    \item 
    Use Case: \textbf{Edit Message}

    \textbf{BASIC COURSE:}

    The system displays the chat window. User clicks on the edit button to edit the message. The system opens the edit message window and displays the message in the text input field. User edits the message and clicks on the save button. The system sends the edited message to the server and displays it in the chat window.

    \textbf{ALTERNATIVE COURSES:}

    \textbf{message not found (already deleted):}
    User tries to edit a message that does not exist. The system does not send the message to the server and displays an error message.

    \item
    Use Case: \textbf{Delete Message}   

    \textbf{BASIC COURSE:}

    The system displays the chat window. User clicks on the delete button to delete the message. The system opens the delete message window and displays the message in the text input field. User clicks on the delete button. The system sends the delete request to the server and deletes the message from the chat window.
    
    \textbf{ALTERNATIVE COURSES:}

    \textbf{message not found (already deleted):}
    User tries to delete a message that does not exist. The system does not send the message to the server and displays an error message.

    \item
    Use Case: \textbf{Pin Message}

    \textbf{BASIC COURSE:}

    The system displays the chat window (private scope chat). User clicks on the pin button to pin the message. The system sends the pin request to the server and displays the pinned message in the chat window.

    \textbf{ALTERNATIVE COURSES:}

    \textbf{message not found (already deleted):}
    User tries to pin a message that does not exist. The system does not send the message to the server and displays an error message.

    \textbf{message already pinned:}
    User tries to pin a message that is already pinned. The system does not send the message to the server and displays an error message.

    \textbf{global scope chat:}
    User tries to pin a message in the global scope chat. The system does not send the message to the server and displays an error message. User is informed that pinning messages is only available in the private scope chat.

    \item 
    Use Case: \textbf{View Pinned Messages}

    \textbf{BASIC COURSE:}

    The system displays the chat window (private scope chat). User clicks on the pinned messages button to view the pinned messages. The system opens the pinned messages window and displays the pinned messages in the chat window. User inputs text on the search bar on the pinned messages window and clicks on the search button. The system searches for the pinned messages in the chat window and displays the results in the pinned messages window.

    \textbf{ALTERNATIVE COURSES:}

    \textbf{pinned messages not found:}
    User opens the pinned messages window but the private scope chat does not have any pinned messages. The system does not display any pinned messages in the chat window and displays an informational message.

    \textbf{search criteria does not match any pinned messages:}
    User inputs text on the search bar on the pinned messages window and clicks on the search button. The system searches for the pinned messages in the chat window and does not find any pinned messages that match the search criteria. The system does not display any pinned messages in the chat window and displays an informational message.

    \item 
    Use Case: \textbf{Unpin Message}

    \textbf{BASIC COURSE:}

    The system displays pinned messages window. User clicks on the unpin button to unpin the message. The system sends the unpin request to the server and unpins the message from the chat window.

    \textbf{ALTERNATIVE COURSES:}

    \textbf{message not found (already deleted):}
    User tries to unpin a message that does not exist. The system does not send the message to the server and displays an error message.

    \textbf{message already unpinned:}
    User tries to unpin a message that is already unpinned. The system does not send the message to the server and displays an error message.

    \item 
    Use Case: \textbf{Search Messages}

    \textbf{BASIC COURSE:}

    The system displays chat panel. User clicks on the search messages icon which opens seperate window for searching messages. User inputs text on the search bar on the search window and clicks on the search button. The system searches for the messages in the chat window and displays the results in the search window. Messages are shown in paginated format. User can scroll down to see more messages. 

    \textbf{ALTERNATIVE COURSES:}

    \textbf{search criteria does not match any messages:}

    User inputs text on the search bar on the search window and clicks on the search button. The system searches for the messages in the chat window and does not find any messages that match the search criteria. The system does not display any messages in the chat window and displays an informational message.

    \textbf{search criteria is empty:}
    User does not input any text on the search bar on the search window and clicks on the search button. The system searches for the messages in the chat window and displays all the messages in the chat window. The system performs view history use case.

    \item 
    Use Case: \textbf{View Message History}

    \textbf{BASIC COURSE:}

    The system displays chat panel. User clicks on the search messages icon which opens seperate window for searching messages. User does not input any text on the search bar on the search window and clicks on the search button. The system searches for the messages in the chat window and displays all the messages in the chat window. Messages are shown in paginated format. User can scroll down to see more messages. 

    \textbf{ALTERNATIVE COURSES:}

    \textbf{user has inputted search criteria:}
    User inputs text on the search bar on the search window and clicks on the search button. The system searches for the messages in the chat window and displays all the messages in the chat window. The system performs a search use case.


\end{itemize}

    \textbf{BASIC COURSE:}

    The system displays game room. User clicks on the on create chat button which opens chat creating window. User chooses group chat. User then chooses the join option and inputs the name of the group chat. The system searches for the group chat and its owner then it sends a request to the group owner to join the group chat. The system displays a message that the request has been sent to the group owner.
    If the group owner accepts the request, the system adds the group chat button. The system sends notifications to the user that they were added.
    If the group owner rejects the request, the system displays a message that the request has been rejected.

    \textbf{ALTERNATIVE COURSES:}

    \textbf{group chat not found:}
    User clicks on the create chat button which opens chat creating window. User chooses group chat. User then chooses the join option and inputs the name of the group chat that does not exist. The system does not send the request to the group owner and displays an error message.

    \textbf{user is already in the group chat:}
    User clicks on the create chat button which opens chat creating window. User chooses group chat. User then chooses the join option and inputs the name of the group chat that user is already in. The system does not send the request to the group owner and immediately adds the group chat button.

    \item 
    Use Case: \textbf{Manage Group Members}

    \textbf{BASIC COURSE:}

    The system displays game room. User clicks on the group chat button which opens group chat window. Then user clicks on the edit group button which opens group edditing window. User can add or remove users from the group chat. The system sends notifications to the users that were added to the group chat. The system sends notifications to the users that were removed from the group chat.

    \textbf{ALTERNATIVE COURSES:}

    \textbf{user is not the group owner:}
    User clicks on the group chat button which opens group chat window. Then user clicks on the edit group button which opens group edditing window. The system does not allow the user to add or remove users from the group chat and displays an error message.

    \textbf{user has not selected any users:}
    User clicks on the group chat button which opens group chat window. Then user clicks on the edit group button which opens group edditing window. User does not select any users to add to the group chat. The system displays an informational message.

    \textbf{the group chat is already deleted:}
    User clicks on the group chat button which opens group chat window. Then user clicks on the edit group button which opens group edditing window. The system does not allow the user to add or remove users from the group chat and displays an error message that the group chat is already deleted.

    \textbf{the group chat is already full:}
    User clicks on the group chat button which opens group chat window. Then user clicks on the edit group button which opens group edditing window. User tries to add users to the group chat but the group chat is already full (100+ users). The system does not allow the user to add users to the group chat and displays an error message.

    \textbf{user has selected too many users:}
    User clicks on the group chat button which opens group chat window. Then user clicks on the edit group button which opens group edditing window. User tries to add too many users (100+) to the group chat. The system does not allow the user to add users to the group chat and displays an error message.

    \item 
    Use Case: \textbf{Start Private Chat}

    \textbf{BASIC COURSE:}

    The system displays game room. User clicks on the on create chat button which opens chat creating window. User chooses private chat. User then chooses the create option and additionally user chooses user to add to the private chat using search functionallity. The system creates the private chat button. The system sends notifications to the user that was added to the private chat.

    \textbf{ALTERNATIVE COURSES:}

    \textbf{user has not selected any user:}
    User clicks on the create chat button which opens chat creating window. User chooses private chat. User then chooses the create option and does not select any user to add to the private chat. The system does not create the private chat button and displays an error message.

    \textbf{user has selected too many users:}
    User clicks on the create chat button which opens chat creating window. User chooses private chat. User then chooses the create option and selects more that one user to add to the private chat. The system does not create the private chat button and displays an error message.

    \item 
    Use Case: \textbf{Switch Chat Scopes}

    \textbf{BASIC COURSE:}

    The system displays game room and room chat. User can click on the room chat chat button to open settings and switch back to global chat. When user has his global chat open, he can click on the chat button to open settings and switch back to room chat.

    \textbf{ALTERNATIVE COURSES:}

    \textbf{room chat cannot be accessed from home page:}
    User in on the home page. User opens up the global chat to try to switch to room chat. The system does not allow the user to switch to room chat and does not display the option to switch to room chat.

    \textbf{private scope chat cannot be changed to global scope chat:}
    User opens up group chat or private chat and searches for the switch from room chat to global chat or vise versa option. The system does not allow the user to switch to global chat (room chat) from private scope (group/private chat) and does not display the option to switch to global chat (room chat).
    
    \item 
    Use Case: \textbf{Change Chat Type}

    \textbf{BASIC COURSE:}

    The system displays game room. User clicks on the chat button icon which opens a seperate menu for choosing a new type for that chat button. User chooses either room chat, group chat or private chat. The system then opens up the create chat window from where user follows the steps already previously described (users selects to create group chat or private chat...).

    \textbf{ALTERNATIVE COURSES:}

    \textbf{only one room chat allowed:}
    User clicks on the chat button icon which opens a seperate menu for choosing a new type for that chat button. User chooses tries to choose room chat option but the system has disabled the option to choose room chat. The system does not allow the user to change the chat type and displays an error message.

    \textbf{changing global chat type in home page is not allowed}
    User clicks on the global chat button icon but it does not open any menus. System does not allow to change global chat type in home page.

    \item 
    Use Case: \textbf{Delete Chat}

    \textbf{BASIC COURSE:}

    The system displays game room. User clicks on the chat button which opens chat window. Then user clicks on the edit chat button which opens either group chat edditing window or private chat edditing window based on chat type. User can delete the group chat or private chat. The system asks for user confirmation. After deletion the system sends notifications to the users that were removed from the group chat or private chat.

    \textbf{ALTERNATIVE COURSES:}

    \textbf{user is not the group owner:}
    User clicks on the chat button which opens chat window. Then user clicks on the edit chat button which opens either group chat edditing window or private chat edditing window based on chat type. The system does not allow the user to delete the group chat or private chat and displays an error message.

    \textbf{chat is already deleted:}
    User clicks on the chat button which opens chat window. Then user clicks on the edit chat button which opens either group chat edditing window or private chat edditing window based on chat type. The system does not allow the user to delete the group chat or private chat and displays an error message that the group chat or private chat is already deleted.

\end{itemize}

    \item 
    Use Case: \textbf{Receive Notification}

    \textbf{BASIC COURSE:}

    \textbf{ALTERNATIVE COURSES:}

    \textbf{the browser window is to narrow:}
    The user receives a notification about new messages/events. The system plays a sound that the user has received a notification but the browser window is too narrow to display the notification. The system does not display an error message.

    \item

    \textbf{BASIC COURSE:}

\subsubsection{Package: UI Interactions}
\begin{itemize}
    \item 
    Use Case: \textbf{Toggle Chat Window}

    \textbf{BASIC COURSE:}

    The system displays game room. User clicks on the chat button which opens chat window. User can click on the close button to close the chat window. The system closes the chat window and displays the chat button again.

    \textbf{ALTERNATIVE COURSES:}

    \textbf{chat window is already open:}
    User tries to open the chat window but the system does duplicate the chat window. The system does not display an error message.

    \item 
    Use Case: \textbf{Create Multiple Chats}

    \textbf{BASIC COURSE:}

    The system displays game room. User can click on the create chat button and then follow the creation proccess on create chat window to opens a new chat button. After that the user can click on the chat button to open a new chat window.
    
    \textbf{ALTERNATIVE COURSES:}

    \textbf{user has too many chat buttons:}
    User tries to create a new chat button using the create chat window process but the system only allows 3 chat buttons (windows if opened) at max. System shows an error message.

    \textbf{user already has a global scope chat open:}
    The system displays game room. User tries to create a new global scope chat (room chat) button using the create chat window process but the system does not allow the user to create a new global scope chat button. The system shows an error message.

    \textbf{chat creation is not allowed in home page:}
    User tries to create a new chat button using the create chat window process but the button is not available. The system does not allow the user to create a new chat button and does not display an error message.

    \item 
    Use Case: \textbf{Select Emoji}

    \textbf{BASIC COURSE:}

    The system displays chat window. User clicks on the emoji button which opens emoji window. User can select an emoji from the emoji window or use search bar. The system adds the selected emoji to the message input field.

    \textbf{ALTERNATIVE COURSES:}

    \textbf{search criteria does not match any emojis:}
    User inputs text on the search bar on the emoji window and clicks on the search button. The system searches for the emojis in the emoji window and does not find any emojis that match the search criteria. The system does not display any emojis in the emoji window and displays an informational message.

    \textbf{user has not selected any emojis:}
    User clicks on the emoji button which opens emoji window. User does not select any emojis from the emoji window. The system does not add any emojis to the message input field and does not display an error message.

    \item 
    Use Case: \textbf{Upload File}

    \textbf{BASIC COURSE:}

    The system displays chat window. User clicks on the file upload button which opens file upload window. User can select a file from the file upload window. User selects a .png, .jpg, .jpeg, .gif file and upload it. The system saves the selected file to the server and displays it in the chat window.

    \textbf{ALTERNATIVE COURSES:}

    \textbf{file type not allowed:}
    User clicks on the file upload button which opens file upload window. User selects a .exe, .bat, .sh file and upload it. The system does not save the selected file to the server and displays an error message.

    \textbf{file size too large:}
    User clicks on the file upload button which opens file upload window. User selects a .png, .jpg, .jpeg, .gif file that is larger than 10MB and upload it. The system does not save the selected file to the server and displays an error message.

    \textbf{file name too long:}
    User clicks on the file upload button which opens file upload window. User selects a .png, .jpg, .jpeg, .gif file that has a name longer than 255 characters and upload it. The system does not save the selected file to the server and displays an error message.
    
    \textbf{file name contains special characters:}
    User clicks on the file upload button which opens file upload window. User selects a .png, .jpg, .jpeg, .gif file that has a name that contains special characters and upload it. The system does not save the selected file to the server and displays an error message.

\end{itemize}
